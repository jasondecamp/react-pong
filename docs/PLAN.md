# react-pong plan

A ground-up rewrite of [jasondecamp/angular-pong](https://github.com/jasondecamp/angular-pong) (Jason's 2016 AngularJS directive, itself based on [strawbserve/angular-pong](https://github.com/strawbserve/angular-pong)) as a framework-free Pong engine with a React component that embeds a playfield in any React app, installable from GitHub. It has the same design and the same game; no code is carried over. Decisions below were settled on 2026-11-03.

## Goals

- A pure, framework-free core that runs a game of Pong and drives a DOM playfield.
- A composite React component, `<Pong>`, that drops a playfield into any React app and plays nicely with the host page: scoped keyboard input, no globals, several instances at once, full teardown.
- Installable as a dependency straight from GitHub (`github:jasondecamp/react-pong#semver:^0.1.0`).
- Look and play like the original: flat `#007ee5` ball and paddles, thin gray score at the bottom center, a fading centered message, 8-bit blips, first to 11.
- Follow the conventions of react-snow, adapted for a component with styles.

## What the original did, and what changes

The original is one AngularJS directive (`<pong-court>`), about 400 lines. You play the right paddle with the up and down arrows against an AI on the left. Enter serves; Esc pauses, resumes, and resets after game over. The first to 11 wins, and the winning score scales up in blue. Every point can post a smack-talk line (`smack`, default off) that fades after 5 seconds. Three `.wav` files play on wall hits, paddle hits, and points.

It doesn't survive being embedded: it listens for keys on `document` (so it would steal the host's arrow keys), keeps the court in an implicit global, reads the court size once, moves everything on 10 ms `$interval`s (speed depends on timer accuracy, and the ball loop's elapsed time is negated), loads sounds from a relative `assets/` path, and needs Angular, ngSanitize, ngAnimate, and Bootstrap on the page.

The rewrite keeps the look, the rules, the feel of the controls, the AI's character, and the copy, and rebuilds everything else.

## Decisions

| # | Topic | Decision |
| --- | --- | --- |
| 1 | Layers | A framework-free core (`react-pong/core`) and a React layer (`react-pong`), as in react-snow. The core never imports React. |
| 2 | Simulation | A pure module: court size, ball, paddles, scores, phase, and AI, advanced by `step(dt, input)` with delta-time physics (px per second, same speed at 60Hz and 120Hz, large `dt` clamped). It never touches the DOM and takes its random source as an input so tests are deterministic. It reports events (`wall`, `paddle`, `point`, `gameOver`) from each step for sound and messages. |
| 3 | Rendering | DOM and CSS. The ball and paddles are elements moved with `transform: translate(...)` written directly from the loop, never through React state. The score and message are real text rendered by React from the game state, so screen readers can read them. Where the ball meets a paddle, two rings ripple outward and fade (`ripple`, default `true`; paddle hits only, not walls). The court holds one optional ripple element per paddle, since hits alternate sides: the simulation records the point of contact, the engine moves that paddle's ripple there and restarts its animation by re-adding a class, and CSS draws the rings on the element's pseudo-elements. Color, size, thickness, and duration are `--pong-ripple-*` properties, and reduced motion hides it. |
| 4 | Core API | `createPong({ court, ball, leftPaddle, rightPaddle }, options)` takes elements it doesn't create (it never inserts DOM). It sizes itself to the court with a `ResizeObserver`, listens for keys on the court element only, and runs a `requestAnimationFrame` loop that idles when nothing moves (between points, paused, game over, offscreen). Instance methods: `serve`, `pause`, `resume`, `reset`, `openHelp`, `closeHelp`, `update(options)`, `getState`, `subscribe(listener)` (`useSyncExternalStore`-shaped, notified only when the score, phase, message, difficulty, winning score, help, or key map changes, never per frame), and `destroy` (stops the loop and releases every listener, observer, and the audio context). |
| 5 | React API | Composite, per the house pattern: `<Pong {...options}>` creates the engine and provides it through context; `Pong.Court` renders the focusable playfield with the ball and paddles; `Pong.Score`, `Pong.Message`, and `Pong.Help` render from state. A bare `<Pong />` renders the default arrangement (court, score, message, help). `Pong.Court` takes `autoFocus`, for pages the game owns. `usePongGame()` exposes state and controls (`serve`, `pause`, `resume`, `reset`, `openHelp`, `closeHelp`) for custom subcomponents. Callbacks `onPoint` and `onGameOver` are options, so the core has them too. SSR-safe: the server renders the static start screen and the engine starts in an effect. |
| 6 | Embedding | `<Pong>` fills its parent (the consumer sizes the parent). Keyboard input only reaches the game while the court has focus: the court has `tabIndex={0}`, an `aria-label`, and a visible focus style, and clicking it focuses it. Keys the game handles call `preventDefault` so arrows don't scroll the page; others pass through. Losing focus, hiding the tab, or scrolling offscreen during a rally pauses it. Any number of instances can run at once. |
| 7 | Controls | As in the original, up and down arrows move the right paddle, Enter serves, and Esc resets after game over. Unlike the original, Space pauses and resumes rather than Esc: pausing (`pause`) and resetting (`reset`) are separate actions, and Esc does nothing during a game. The paddle accelerates the longer the key is held, as before, with its speed in court heights per second. Unlike the original it doesn't jump to its starting speed: it eases in over the first 0.08s (a quadratic ease-in). A `keys` option remaps them: a map from `KeyboardEvent.key` to action that replaces the default map, so several keys can share an action. Keys pressed with Ctrl, Alt, or Meta are left to the page. Two keys are new. `?` (`help`) opens the help, an overlay listing every key in the current key map with what it does, headed by the score to play to ("First to 11 wins") and followed by an "Advanced" section explaining that a moving paddle adds momentum to the ball and that a paddle's corners send it off steeply; it pauses a rally first, and while it is open only the help and reset keys do anything, both of which close it, leaving the rally paused. `d` (`difficulty`) steps the difficulty through easy, normal, and hard, but only between games (on the start screen and after game over), never during one; `onDifficultyChange` reports each step so a controlled `difficulty` can follow, and the `difficulty` option itself still applies at any time. The engine owns both and reports `help`, `difficulty`, `winningScore`, and `keys` in its state; `Pong.Help` renders the overlay and, just above the score, a "press ? for help" hint and, above that, the current difficulty in its own color (`--pong-difficulty-*-color`), shown only between games. How to change the difficulty is explained only in the overlay, whose row for the key says it doesn't work during a game. Pointer and touch control and two-player mode are out of scope for 1.0. |
| 8 | Rules and physics | First to `winningScore` (default 11), no win-by-two. The first serve goes to a random side, then the side that scored serves from its own paddle, as in the original. Unlike the original, the first serve is shown being decided (`toss`, default `true`): the simulation picks the side, enters a `toss` phase, and bounces the ball between the paddles from the middle of the court, 3.5 crossings in 1.8 seconds, easing to rest on the server's paddle, with each bounce blipping and rippling like a hit. It then reports the server (messages `serve.ai` and `serve.human`, "My serve." and "Your serve.") and counts 3-2-1 at 0.6 seconds a number (`countdown` in the state, a blip on each) before serving. The human paddle can move throughout, and the ball rides the server's paddle during the count. Game keys other than the paddle's do nothing until the ball leaves. Reduced motion skips the bouncing and keeps the announcement and countdown. Losing focus, hiding the tab, scrolling offscreen, or opening the help calls the toss off and returns to the start screen. Only the first serve of a match is tossed for. The ball has a speed and an angle rather than separate horizontal and vertical speeds, so its pace is predictable (the original's serves were slow across and anything from flat to very steep). Serves leave at 0.65 court widths per second, give or take a tenth, within 30° of level. Each paddle hit adds 5% to the speed. A moving paddle drags the ball with it: half the paddle's vertical velocity at impact is added to the ball's before the new angle is worked out, so a paddle pinned against a wall adds nothing. A ball that catches a paddle within one ball size of its top or bottom edge has hit the corner and leaves at 70° toward the ceiling or floor, whatever the paddle was doing. The same goes for a ball that has got past the paddle's face and is then caught by the paddle's top or bottom end before it reaches the edge of the court, usually because the paddle ran into it: it comes back at the full 80° away from that end, with no random variation, and the sweep covers the paddle's movement too, so a fast paddle can't skip over the ball. Every hit on a paddle's face also varies the angle by up to 3° at random, and the path is never steeper than 80°. Walls mirror the angle. Positions scale proportionally when the court resizes. Collision is swept, so a fast ball can't tunnel through a paddle. |
| 9 | AI | The left paddle. `difficulty: 'easy' \| 'normal' \| 'hard'`, default `'normal'`. All three keep the original AI's character: deciding 100 times a second, it mostly follows the ball once the ball is inside its zone, sometimes gives up, and doesn't set off after a ball that is level with its paddle. They differ in the zone, measured across the court from the AI's edge: the nearest third on `easy`, its own half on `normal`, the nearest two thirds on `hard`. They also differ in what the paddle does once it has sent the ball away. It doesn't follow the departing ball: it decides at that instant where to wait, goes there, and stays until the ball is back inside its zone. On `easy` that is level with where the ball will reach the opponent (where the opponent should stand), on `normal` a random height, and on `hard` where the ball will come back to if it bounces off the walls and the opponent's paddle without any change of angle. It also plays shots rather than always meeting the ball squarely. When the ball is sent its way it decides how to return it: half the time by swinging up or down through the ball, so its momentum bends the path (it hangs back by the distance it will cover, then starts moving 0.2s before the ball arrives, which is long enough to ease in to full speed); 15% of the time by lining up its top or bottom corner; otherwise with the middle of its paddle. The mix is the same at every difficulty for now. The presets are tuned in the playground. |
| 10 | Attract mode | `attract` (default `true`): on the start screen, before the first serve, both paddles are played by the AI behind the "Shall we play a game?" message, like an arcade cabinet. Attract rallies make no sound and score nothing. Enter resets the court and serves the real game. Reduced motion turns it off. |
| 11 | Sound | Synthesized with Web Audio: three short square-wave blips (wall, paddle, out) close to the original 8-bit wavs, with no asset files. The `AudioContext` is created lazily on the first key press (browsers block audio until a gesture) and closed on `destroy`. `sound` (default `true`) turns it off. |
| 12 | Messages | The core reports a message key (`start`, `toss`, `serve.ai`, `serve.human`, `smack.ai`, `smack.human`, `paused`, `gameOver`, `reset`), not text, with a count of earlier messages with that key in the match and a random roll drawn per match, so copy can be dealt from a deck shuffled once per match. `reset` is the original's "press esc to reset", shown when Enter is pressed after game over. `paused` is new copy ("PAUSED", "press space to resume"); the original said nothing while paused. `Pong.Message` maps keys to the original copy, deals smack lines from the original's lines plus new ones in the same voice (mostly sore-loser lines for when the human scores), shuffled per match so none repeats within a match until every line has been said, and fades out after 5 seconds. `smack` (default `true`) is smack talk, set in the AI paddle's color (`--pong-smack-color`), which follows about half the points rather than every one, so it stays a surprise. Hint text ("press enter to start") is set in smaller uppercase gray, as before. Custom copy means replacing `Pong.Message` with your own subcomponent over `usePongGame()`. |
| 13 | Styles | The package ships a plain CSS file, `react-pong/styles.css`, that consumers import once. Class names are prefixed (`pong-`) to avoid collisions. The defaults sit on the root in `:where(.pong)`, so consumers set properties through `<Pong>`'s `className`. Colors, sizes, and the font are `--pong-*` custom properties with the original's values as defaults (`--pong-color: #007ee5`, `--pong-muted: #ccc`, ball and paddle `15px`, paddle height 15% of the court). The ball and each paddle also have their own color property. These depart from the original, where everything was the one blue: the ball (`--pong-ball-color`) is black, the AI's paddle (`--pong-paddle-left-color`) is a dark maroon, `#a61c28`, and the human's (`--pong-paddle-right-color`) follows `--pong-color`. Smack talk is the AI speaking, so it is set in the AI paddle's color (`--pong-smack-color`). The message size default is `52px`, up from the original's `30px`. Transitions (message fade, winner scale-up) are disabled under `prefers-reduced-motion`. |
| 14 | Font | The library loads no font: `--pong-font` defaults to `inherit`, with weights 100 and 700 as in the original. The playground loads Roboto to recreate the original look. |
| 15 | Language and distribution | As react-snow: TypeScript (`strict`), compiled by plain `tsc` (TypeScript pinned to 6.0 until typescript-eslint supports 7) to per-file ESM `.js` + `.d.ts` in `dist/`, with `jsx: react-jsx`; the build copies `styles.css` alongside. `exports`: `.` (React), `./core`, and `./styles.css`. `react` (>= 19) is a peer dependency, optional for core-only use. `sideEffects` lists only the CSS. `dist/` is git-ignored on `main` and exists only on release tags. |
| 16 | Repo | `~/work/react-pong`, public GitHub repo `jasondecamp/react-pong`. Node 24, pnpm 12, ESLint 10 flat config with the react-snow rules, Vitest (simulation in `node` with injected random; engine, hook, and components in jsdom). Feature branches and PRs; CI runs lint, typecheck, test, and build on every PR. MIT license, crediting angular-pong and strawbserve/angular-pong (clean-room rewrite, no code copied). |
| 17 | Releases | As react-snow: bumping `version` in a PR and merging it releases (lint, test, build, commit `dist/` in a release-only commit, tag `v<version>`, GitHub Release). Merges without a bump don't release. `0.x` until the physics and AI are tuned. |
| 18 | Demo | A Vite playground in `demo/` (not in the package) importing from `src/`, full-window like the original's page, with Roboto loaded and a panel for every option and the theme variables. Deployed to GitHub Pages by `release.yml` at `https://jasondecamp.github.io/react-pong/` from 0.1.0. |

## Options (defaults to be tuned in the playground)

| Option | Default | Notes |
| --- | --- | --- |
| `winningScore` | `11` | |
| `difficulty` | `'normal'` | `'easy'`, `'normal'`, or `'hard'`. |
| `attract` | `true` | AI vs AI on the start screen. From 0.2.0. |
| `smack` | `true` | Smack talk after about half the points. |
| `sound` | `true` | Web Audio blips. |
| `ripple` | `true` | Rings rippling out from where the ball meets a paddle. |
| `toss` | `true` | A toss for the first serve of each match, then a 3-2-1 countdown. |
| `keys` | arrows, Enter, Space, Esc, ?, d | Maps `KeyboardEvent.key` values to `up`, `down`, `serve`, `pause`, `reset`, `help`, `difficulty`. |
| `paddleSpeed` | `1.2` | Starting paddle speed, in court heights per second (the original's nominal 1000 px/s on a window about 830px tall), so it scales with the court like the ball does. Held, it reaches three times this over two seconds. |
| `onPoint`, `onGameOver`, `onDifficultyChange` | | Callbacks. |

## Layout

```
src/
  core/        # simulation (pure), ai, sound, createPong, options, types, index.ts
  react/       # Pong.tsx (+ Court, Score, Message, Help), usePongGame.ts, pongStore.ts, index.ts
  styles.css   # copied to dist/ by the build
demo/          # Vite playground (not published)
docs/PLAN.md
.github/workflows/  # ci.yml, release.yml
```

## Phases

1. **0.1.0:** the faithful game. Repo scaffolding, simulation, the AI and its `difficulty` presets, Web Audio sound, `createPong`, the composite component, `styles.css`, tests, the playground and its Pages deploy, README, CI, release workflow.
2. **0.2.0:** attract mode (decision 10).
3. **1.0.0:** physics, AI presets, and sound tuned in the playground.

- Pointer and touch control, two-player mode: later, if wanted.
